# ioncube-strip — Installation Guide

## System Requirements

| Component | Version | Notes |
|-----------|---------|-------|
| OS | Linux (tested), macOS | Primary target: Linux |
| Python | 3.8+ | For pool extraction |
| PHP | 5.6 CLI | **Required for dump stage** |
| arm56 | Custom build | PHP extension for ionCube hooking |

## Python Dependencies

```bash
pip install -r requirements.txt
# Or manually:
pip install pyyaml ruff pytest
```

## PHP 5.6 Installation

### Ubuntu/Debian (using ondrej PPA)

```bash
sudo add-apt-repository ppa:ondrej/php
sudo apt update
sudo apt install php5.6-cli php5.6-dev php5.6-common
```

### Compile from Source

```bash
# Install build dependencies
sudo apt install build-essential libxml2-dev libssl-dev libsqlite3-dev \
    libbz2-dev libcurl4-openssl-dev libjpeg-dev libpng-dev libfreetype6-dev \
    libonig-dev libzip-dev libreadline-dev libedit-dev

# Download and compile
wget https://museum.php.net/php5/php-5.6.40.tar.gz
tar xzf php-5.6.40.tar.gz
cd php-5.6.40
./configure --prefix=/usr/local/php56 \
    --enable-cli \
    --with-config-file-path=/etc/php56 \
    --with-openssl \
    --with-curl \
    --with-zlib \
    --enable-mbstring \
    --enable-sockets
make -j$(nproc)
sudo make install
```

### Verify PHP 5.6

```bash
/usr/local/php56/bin/php -v
# Should show: PHP 5.6.x (cli)
```

## arm56 Extension Build

There are two generations of the arm56 extension and they are not
interchangeable. See `docs/CONFIGURATION.md`, "Two arm56 generations", for the
full comparison before you build anything.

| | v4 — in this repository | legacy — not in this repository |
|---|---|---|
| Needed for | `manifest`, `symbols` | `dump`, `pool` |
| Output | JSON (`ARM56_JSON`) | hex dumps (`ARM56_TMP`) |
| Source | `arm56/arm56.c` here | external; see below |

Build **v4** unless you specifically need the legacy hex-dump behaviour.

### v4 source

`arm56/arm56.c` is first-party source in this repository, along with
`arm56/config.m4`. It self-describes as "arm56 v4 (E1 spike)" and exports
`arm56_version()` and `arm56_dump()`.

Note that `arm56/configure.in` and `arm56/config.h.in` are deliberately not
tracked: they are regenerated by `autoconf`/`autoheader`. Everything
`autoreconf` produces is ignored, and only `arm56.c` and `config.m4` are
committed. If you change the build inputs, re-run `autoreconf` rather than
editing a generated file.

### Build Requirements

- PHP 5.6 development headers (`php5.6-dev` or compiled source)
- GCC compatible with PHP 5.6 (GCC 7-9 recommended)
- `autoconf`, `automake`, `libtool` (to regenerate the build system)

### Build Steps

```bash
cd arm56

# Set PHP 5.6 paths
export PHP_PREFIX=/usr/local/php56
export PATH=$PHP_PREFIX/bin:$PATH

autoreconf          # only if config.m4 changed
phpize
./configure --with-php-config=$PHP_PREFIX/bin/php-config
make

# Install
sudo make install
# Or manually copy:
# cp modules/arm56.so /usr/local/lib/arm56.so
```

### Verify arm56

```bash
# Which generation is this? Authoritative, from the extension itself.
python3 lib/probe_arm56.py --config config/ioncube-strip.yaml.example
# v4:  arm56 generation: v4 (4.0.0-spike)

# Check the extension loads
/usr/local/php56/bin/php -c /etc/php56/php.ini \
  -d extension=/usr/local/lib/arm56.so -m | grep arm56
# Should show: arm56
```

`extension=`, not `zend_extension=`: arm56 declares a plain
`zend_module_entry` with `STANDARD_MODULE_HEADER` and `PHP_MINIT`
(`arm56/arm56.c:950`), so it is an ordinary extension. Loading it as a
`zend_extension` fails with *"doesn't appear to be a valid Zend extension"* and
`arm56_version()` is then absent — which the probe would report as
`unverified`, i.e. a wrong answer rather than an error.

Ordering still matters, and it is the *Loader* that must come first, not arm56:
the Loader aborts unless it is the first `zend_extension` in `php.ini`.

### legacy source

The legacy hex-dump extension is not in this repository. It was available from
the WHMCS un-encryption project or ionCube community forks. Without it, `dump`
and `pool` will collect nothing — and `docs/CONFIGURATION.md` records a finding
that may mean they have no output to produce at all.

## PHP 5.6 INI Configuration

Create `/etc/php56/php.ini` (or your chosen path):

```ini
; Minimal PHP 5.6 config for ioncube-strip
extension=arm56.so

; Memory and execution limits
memory_limit = 256M
max_execution_time = 300

; Error handling
error_reporting = E_ALL & ~E_DEPRECATED & ~E_STRICT
display_errors = Off
log_errors = On
error_log = /tmp/php56_errors.log

; Disable unnecessary extensions
disable_functions = exec,passthru,shell_exec,system,proc_open,popen
```

## ioncube-strip Configuration

Copy and customize the example config:

```bash
cp config/ioncube-strip.yaml.example ioncube-strip.yaml
```

Edit `ioncube-strip.yaml` with your paths:

```yaml
toolchain:
  php56: "/usr/local/php56/bin/php"
  php56_ini: "/etc/php56/php.ini"
  arm56_so: "/usr/local/lib/arm56.so"
  arm56_tmp: "/tmp/arm56_output"
```

Or use environment variables (override config):

```bash
export PHP56=/usr/local/php56/bin/php
export PHP56_INI=/etc/php56/php.ini
export ARM56_SO=/usr/local/lib/arm56.so
export ARM56_TMP=/tmp/arm56_output
```

## Troubleshooting

### "PHP 5.6 not found"
- Verify `PHP56` path in config or env
- Check binary is executable: `ls -la $PHP56`

### "arm56.so not found"
- Verify `ARM56_SO` path
- Rebuild arm56 against your PHP 5.6
- Check `php -m` shows arm56

### "the loaded arm56 is the in-tree v4 build"
- Expected. `dump` needs the legacy hex-dump extension; v4 writes JSON and
  would collect nothing anyway. Use `ioncube-strip symbols` or
  `ioncube-strip manifest` instead.

### "No dumps collected" / pool stage reports nothing
- Almost always the wrong arm56 generation, not an empty file. Run
  `python3 lib/probe_arm56.py` and read `docs/CONFIGURATION.md`,
  "Two arm56 generations".
- Note that even with the legacy build, literal pool *content* may be
  unrecoverable: see the "Neither recovers method bodies" section of
  `docs/CONFIGURATION.md`.

### "The Loader must appear as the first entry in the php.ini file"
- The ionCube Loader must be the first `zend_extension` in `php56_ini`. arm56
  itself is a plain `extension=`, loaded after the Loader. Reorder `php.ini`
  accordingly, and note that a distro php.ini loading opcache as a
  `zend_extension` will conflict — use a dedicated ini, which is what
  `PHP_INI_SCAN_DIR=''` in the tool supports.

### "Permission denied on /tmp/arm56_output"
- Ensure directory exists and is writable
- Or set `ARM56_TMP` to a writable location
  (legacy generation only; v4 uses `ARM56_JSON`)

### "PHP 5.6 segfaults on include"
- Check PHP 5.6 compiled with `--enable-debug` for backtrace
- Verify ionCube file is actually 5.x format
- Try with minimal ini (disable all non-essential extensions)

### Build fails on modern GCC
- Use GCC 7-9: `export CC=gcc-9 CXX=g++-9`
- Apply compatibility patches to arm56 source if needed
